# Визуальная концепция сайта БАСТ: «Живая сделка»

Дата: 2026-07-10
Статус: утверждена (концепция), реализация — отдельным планом

## Контекст

Независимый аудит сайта (2026-07-10) показал: визуальный язык сильный, но без стержня —
нет идеи, которая диктует, что снимать, где тёмное/светлое и как показывать приложение.
Ключевые проблемы: нарисованные мокапы вместо реального продукта, терракотовый акцент,
которого нет в приложении, частое чередование тёмных/светлых секций («зебра»),
страницы-заглушки /how-it-works и /product, на которые ведут заметные CTA.

Вводные, зафиксированные на брейнсторме:

- **Главный адресат концепции — инвестор.** Сайт должен демонстрировать зрелость
  продукта и системность команды. Покупатели и B2B обслуживаются, но эмоциональный
  регистр настроен на инвестора.
- **Фактура — HTML-копии реальных экранов приложения с демо-данными.** Не стилизованные
  фантазии и не PNG-скриншоты.
- **Палитра приложения не меняется.** Источник правды — токены
  `bast/shared/designSystem/theme` (сайт наследует их, не наоборот).
- Продукт двухрегистровый: **для покупателя — витрина, для риэлтора и застройщика — CRM.**

Рассматривались три варианта: «Мечта и порядок» (эволюция), «Инфраструктурный слой»
(геодезическая разметка), «Продукт показывает себя сам». Выбран третий.

## Центральная идея

> Сайт — не рассказ о приложении, а непрерывная демонстрация одной сделки.
> Продукт показывает себя сам.

Через весь сайт проходит **одна сквозная демо-сделка** с постоянными участниками:
покупатель находит «Дом у леса, 184 м²» за 12,8 млн ₽, пишет продавцу, закрепляется
за риэлтором, стартует сделка, объект проходит проверку, договор готовится, документы
подписаны. Все экраны на всех страницах показывают эту сделку на разных стадиях.

Что это даёт:

- **Инвестору** — наблюдает работающий продукт от начала до конца, не скачивая его.
- **Структуре** — история диктует порядок блоков; перескоки аудиторий исчезают.
- **Консистентности** — один канонический набор демо-данных как часть дизайн-системы.

## Канон демо-сделки

Единый набор демо-данных, обязательный для всех экранов на сайте:

- Объект: «Дом у леса», 184 м², Завьяловский район, кп «Сосновый бор»,
  12 800 000 ₽ (69 600 ₽/м²), кирпич, 2025, газ, 2 санузла, 4 спальни, 2 этажа, 9 соток.
- Участники: покупатель, риэлтор (автор привязки), продавец-застройщик.
  Имена и аватары — задать при вёрстке один раз, зафиксировать в канон-файле.
- Хронология: время в чатах и статусах движется вперёд по мере скролла.
- Этапы: сделка начата → объект выбран → договор готовится → документы подписаны.

Канон хранится одним файлом данных (constants) в кодовой базе сайта; экраны-копии
рендерятся из него.

## Палитра — наследуется из приложения

| Роль на сайте | Токен приложения | Значение (light) |
|---|---|---|
| Бумага (база страницы) | `canvas` | `#F7F8F5` |
| Поверхности, карточки, экраны | `surface` | `#FFFFFF` |
| Текст, тёмные якоря (hero, CTA) | `graphite` / dark bg | `#23262F` / `#0F1217` |
| Живость продукта: статусы, прогресс, «Проверено», чат | `trust` | `#2F6B5F` |
| Премиум-акцент: сертификаты, ключевые цифры, точка логотипа | `accent` (gold) | `#C8A96A` |
| CRM-подложки и тёмные экраны | dark `surface` | `#1A1D24` |

Правила:

- Терракота текущего сайта **уходит полностью**; тепло остаётся в фотографии.
- Бледно-мятные секции уходят; одна светлая база вместо двух.
- Trust-зелёный на «бумаге» используется только там, где продукт что-то делает,
  и никогда — как декоративная заливка. Глаз выучивает: зелёное = продукт работает.
- Золото — дозированно, «специя»: не больше одного золотого элемента на экран.
- Пропорция светлого/тёмного на странице ≈ 80/20.

## Два регистра

- **Витрина (покупатель):** экраны в светлой теме приложения, фото домов, воздух.
  Живёт на светлых секциях. Страницы: главная (покупательская линия), /buyers.
- **CRM (риэлтор, застройщик):** экраны в тёмной графитовой теме (`#1A1D24`),
  списки клиентов, сделки, обращения. Графитовые подложки секций. Страницы:
  /agencies, /developers, CRM-интермедия главной.

Считывается без слов: светлое — «мне ищут дом», графитовое — «здесь работают
профессионалы». Инвестор видит оба регистра — «витрина + CRM» становится
визуальным фактом. /investors показывает оба регистра рядом.

## Типографика — три голоса

1. **Антиква** (текущая заголовочная) — только H1 hero и заголовок финального CTA.
   «Рамка» премиальности: первое и последнее слово — фирменным голосом.
2. **Гротеск** — все остальные заголовки и текст. Заголовки секций сдержаннее
   и меньше текущих: они подписи к демонстрации, а не главные герои.
3. **Моно / табличные цифры** — демо-данные: цены, тайминги, номера этапов.

Типографические нормы ru-text сохраняются: «ёлочки», тире «—», неразрывные пробелы.

## Хореография главной — пять актов

Десктоп: sticky-телефон в центральной полосе, текст скользит рядом, экран живёт.

1. **Поиск** — каталог с картой, карточка «Дом у леса» (витрина).
2. **Диалог** — в чате печатается вопрос, приходит ответ продавца.
3. **Старт сделки** — появляются участники, клиент закрепляется за риэлтором.
4. **Проверка и этапы** — чек-лист проверки отмечается, прогресс заполняется.
5. **Подпись** — этап завершается, переход к CTA.

Между актами 3 и 4 — **CRM-интермедия («переворот камеры»)**: графитовый разворот,
та же сделка глазами риэлтора (клиент закреплён, авторство) и застройщика
(обращение, ответственный).

Правила движения:

- Анимируются **только состояния продукта**: сообщение печатается, галочка
  зажигается, прогресс заполняется. Никаких декоративных параллаксов.
- 300–400 мс, только transform/opacity, цель 60 fps.
- Мобильный: без sticky-телефона; экраны инлайн как «кадры», запуск по
  IntersectionObserver.
- `prefers-reduced-motion` / без JS: статичные ключевые кадры каждого акта.

## Фотография

- Роль второго плана: hero и CTA — подложки, тонированные графитовым градиентом;
  остальное фото — контент внутри экранов приложения.
- 6–8 уникальных кадров одной серии: загородные дома, естественный утренний/вечерний
  свет, тёплые тона. Фоновые кадры не повторяются.
- «Дом у леса» — один и тот же кадр во всех экранах демо-сделки (консистентность
  истории, не повтор).
- /about — реальные фото команды в той же тональности.

## Ритм главной

Графитовый hero (антиква + телефон, акт 1) → бумага: акты 2–5 → графитовая
CRM-интермедия → бумага: проверка, география, FAQ → графитовый CTA с QR-кодами.

## Риски и страховки

| Риск | Страховка |
|---|---|
| Скатиться в типовой SaaS-лендинг | Тёплая бумага вместо белого, антиква-рамка, воздух, никаких стоковых градиентов; премиальность = качество исполнения демонстрации |
| Скролл-хореография дорогая и хрупкая | Только transform/opacity; статичные ключевые кадры как деградация; мобильный без sticky |
| Демо-данные разъедутся между экранами | Единый канон-файл данных, экраны рендерятся из него |
| Экраны-копии отстанут от реального приложения | Копии строятся по токенам приложения; сверка при мажорных изменениях UI |

## Вне охвата

- Изменения палитры и UI самого приложения.
- Наполнение /product контентом (допускается временный редирект).
- Съёмка фотосерии и команды (отдельная задача; до неё — текущие лучшие кадры).
- Тексты страниц (контент-воркстрим по спеке 2026-07-06 продолжает действовать;
  формулировки адаптируются под акты демо-сделки на этапе плана).

## Критерии успеха

1. Экран приложения на сайте неотличим от реального приложения (палитра, данные).
2. Скролл главной прочитывает сделку от поиска до подписи без единого клика.
3. Регистры «витрина/CRM» различимы без чтения текста.
4. Ни одного нарисованного «фантазийного» интерфейса, которого нет в продукте.
5. CTA «Посмотреть этапы сделки» ведёт на страницу, где этапы действительно показаны.
